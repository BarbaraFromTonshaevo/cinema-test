# Витрина онлайн-кинотеатра

[English](README.md) | **Русский**

Главная страница онлайн-кинотеатра на Nuxt 3, TypeScript, Pinia и Tailwind CSS: адаптивная сетка карточек, в которых ссылки на жанры и метки (`genre:6`, `label:4`) заменяются объектами из справочников CMS.

> 💼 **Тестовое задание** · Джаст Ворк, позиция фронтенд-разработчика · январь 2026. ТЗ просило решение «production-уровня» — старт проекта большого кинотеатра, который работает для любых справочников и страниц, в режимах SSR/SSG и SPA. Исходное решение — первые четыре коммита (28–30 января); всё, что добавлено позже, перечислено в разделе [Что изменено позже](#что-изменено-позже).

## Ключевое

- **DTO отдельно от модели страницы.** Компоненты работают с доменными типами (`Banner`, `Genre`, `Label`, `MainPage`); формат API знает только маппер.
- **Нормализованные справочники.** Жанры и метки загружаются в Pinia один раз и хранятся словарём `oid → объект`, поэтому замена ссылки — это поиск по ключу, а не проход по массиву.
- **Работает в SSR, SSG и SPA** — все три режима из ТЗ проверены, в том числе при недоступном API.
- **Демо переживает падение API.** Снапшот реальных ответов служит фолбэком — урок из [vue2-project](https://github.com/BarbaraFromTonshaevo/vue2-project), где учебное API выключили.

## Возможности

- Главная страница с SSR: браузер получает готовый HTML с данными.
- В карточке — название, синопсис (обрезается до трёх строк), картинка, жанры и метки.
- Ссылки на отсутствующие записи справочника отбрасываются и не ломают карточку.
- Адаптивная сетка: 1 колонка на мобильном, 2 на планшете, 3 на десктопе.

## Архитектура

```
CMS API ──► services/api.ts ──► stores/genres.ts, stores/labels.ts   (oid → объект)
   │         (фолбэк на                          │
   │          data/snapshot/)                    ▼
   └──────► pages/index.vue ──► services/mappers/main-page.mapper.ts ──► components/card/banner.vue
            useAsyncData          DTO → MainPage, ссылки → объекты         карточка в сетке
```

1. [app.vue](app.vue) при старте загружает справочники: `fetchGenres()` и `fetchLabels()`.
2. [stores/genres.ts](stores/genres.ts) и [stores/labels.ts](stores/labels.ts) хранят их словарями по `oid` и отдают через `getGenre(oid)` / `getLabel(oid)`. Состояние Pinia передаётся с сервера на клиент, поэтому повторных запросов нет.
3. [pages/index.vue](pages/index.vue) запрашивает витрину через `useAsyncData`.
4. [services/mappers/main-page.mapper.ts](services/mappers/main-page.mapper.ts) превращает каждый `BannerDTO` в `Banner`: выбирает картинку и заменяет `oid` жанров и меток объектами из сторов.
5. [components/card/banner.vue](components/card/banner.vue) рисует карточку и ничего не знает об API.

### Снапшот API

- В [data/snapshot/](data/snapshot/) лежат реальные ответы `mainpage`, `genres` и `labels`; картинки баннеров — в [public/snapshot/](public/snapshot/).
- `fetchApi(path)` в [services/api.ts](services/api.ts) ходит в API с таймаутом и при ошибке берёт данные из снапшота. Снапшот подгружается динамическим импортом и не попадает в основной бандл.
- `NUXT_PUBLIC_API_SNAPSHOT=true` включает снапшот принудительно; `npm run snapshot:update` обновляет его.
- API отдаёт CORS-заголовки только для своего домена, поэтому в SPA-режиме на другом домене страница рендерится из снапшота. На SSR это не влияет.

### Ключевые решения

- **Отдельный слой маппинга** (`services/mappers/`): преобразование данных не смешивается с запросами и шаблонами.
- **SSR через `useAsyncData`:** страница приходит с данными, а состояние сторов переезжает на клиент через payload.
- **Типизированные ссылки:** `oid` описаны шаблонными строковыми типами (`` `genre:${string}` ``).

## Запуск

Нужен Node.js 20+.

```bash
npm install
npm run dev          # http://localhost:3000
```

Другие скрипты:

```bash
npm run build            # SSR-сборка в .output/
npm run preview          # запуск собранного приложения
npm run generate         # статическая генерация (SSG)
npm run lint             # ESLint
npm run snapshot:update  # обновить снапшот API и картинок
```

Все переменные необязательны; значения по умолчанию — в [nuxt.config.ts](nuxt.config.ts), пример — в [.env.example](.env.example).

| Переменная | По умолчанию | Назначение |
| --- | --- | --- |
| `NUXT_PUBLIC_API_BASE` | `https://cms.test.ksfr.tech/api/v1/` | базовый URL API |
| `NUXT_PUBLIC_API_SNAPSHOT` | `false` | `true` — всегда брать данные из снапшота |
| `NUXT_PUBLIC_API_TIMEOUT` | `3000` | сколько мс ждать API перед фолбэком |

## Что бы я улучшила

ТЗ просило решение для всех справочников и любых страниц; сейчас оно покрывает главную и два её справочника.

- **Универсальный резолвер ссылок.** В API восемь справочников; один стор `metadata` и рекурсивный резолвер обработали бы любую страницу без правок маппера.
- **Прокси к API через серверные маршруты Nitro** — чтобы убрать проблему CORS в SPA-режиме и кешировать справочники.
- **Состояния ошибки и загрузки** из `useAsyncData`, `try/finally` в сторах и параллельная загрузка через `Promise.all`.
- **Строгая типизация маппера** вместо `any`.
- **Ссылки карточек, градиентные метки, SEO-мета и юнит-тесты** маппера и сторов.
- **Порядок в стилях:** `assets/css/main.css` написан в синтаксисе Tailwind 4 при установленном Tailwind 3 и нигде не подключён.
